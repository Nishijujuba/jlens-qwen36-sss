Lesson 0003

WSL、显存预算与模型选择

本课基于 RTX 3080 Laptop 16 GB 专用显存、约 32 GB 系统内存和 WSL 环境，判断原项目能否本地运行，并给出分阶段模型方案。

约 15 分钟 硬件决策 可执行检查

结论先行：该笔记本适合用 Qwen3.5-0.8B-Base 建立可解释性实验闭环，再升级到 Qwen3.5-2B；原仓库的 Qwen3.6-27B + MLX/Metal 完整路径不适合作为本地起点。

1. 先纠正模型名称

仓库名容易造成误解 jlens-qwen36 中的 “36” 指 Qwen 3.6 版本。仓库默认模型是 Qwen3.6-27B，参数量为 27B。它并非一个 36B 参数模型。

Qwen3.6-27B 具有 64 层和 5120 隐藏维度，并混合使用 Gated DeltaNet 与全注意力。仓库针对这套架构实现了专用读出、缓存和反向路径。

2. 原项目受两个独立约束

约束 A：平台

项目依赖 MLX、mlx-lm 和自定义 Metal GDN 反向内核。Metal 属于 Apple 平台。WSL 中的 RTX 3080 使用 CUDA。

MLX 已出现 Linux/CUDA 支持路径，当前仓库仍明确标记 Apple/MLX only，性能关键的 GDN 反向实现仍是 Metal 专用。完整 CUDA 路径需要移植和重新验证。

约束 B：内存

27B 模型的 4-bit 权重理论下限约 13.5 GB。实际加载还包括量化尺度、元数据、未量化模块、运行工作区、激活、缓存和 lens。

仓库的全深度 fp16 lens 本身约 3.3 GB。16 GB 专用显存无法同时为全部组件留下可靠余量。

两个约束需要分别解决。增加内存不会自动获得 Metal 兼容性；移植到 CUDA后仍要重新计算显存预算。

3. 显存到底被什么占用

BUCKET 1模型权重长期驻留的参数
BUCKET 2推理状态激活、KV/GDN 缓存、工作区
BUCKET 3分析开销Jacobian、梯度图、lens、临时矩阵

最简单的权重估算为：

权重体积 ≈ 参数量 × 每个参数的字节数
数值格式理论字节/参数常见用途
FP324高精度计算与部分累加
BF16 / FP162GPU 推理、梯度与可解释性实验
8-bit约 1，加元数据节省推理内存
4-bit约 0.5，加元数据更激进的推理压缩
量化的隐藏代价 4-bit 能显著缩小权重。Jacobian、梯度和因果干预还依赖可微算子、激活精度和临时张量。能完成量化推理，无法直接推出能完成梯度型可解释性实验。

共享 GPU 内存的含义

任务管理器显示约 15.9 GB 共享 GPU 内存。这部分容量来自系统 RAM，经较慢的数据路径访问。它不能按额外 15.9 GB 高速显存计算。模型溢出到共享内存或 CPU 后，速度、延迟和稳定性都会明显恶化。

5. 为什么第一阶段选择 Base 模型

Qwen/Qwen3.5-0.8B-Base 更适合第一个受控实验：

  • 模型规模小，BF16 下仍有足够显存保存激活和梯度图。
  • 同属 qwen3_5 架构家族，术语和部分代码结构可迁移回原仓库。
  • Base 模型直接执行下一词预测，减少聊天模板、系统提示和后训练行为引入的变量。
  • 24 层、隐藏维度 1024，使显式小型 Jacobian 或分层实验仍有可控成本。

第二阶段再换成 Qwen/Qwen3.5-2B，检查结论是否随模型能力提高而保持。模型升级应由实测峰值显存、每词元速度和实验稳定性决定。

6. 在 WSL 内完成环境验收

先验证 GPU 是否真正暴露给 WSL，再安装或调整 Python 环境。Windows PowerShell 中执行：

wsl --version
wsl -l -v

目标是看到 WSL 2。随后进入 WSL，执行：

nvidia-smi
nvidia-smi --query-gpu=name,memory.total,driver_version --format=csv,noheader

目标是看到 RTX 3080 Laptop、约 16 GB 显存和驱动版本。NVIDIA 的 Windows 驱动会把 CUDA 能力暴露到 WSL。不要在 WSL 内安装 Linux 显示驱动；这可能覆盖或冲突 WSL 的驱动映射。

已有 PyTorch 环境时继续执行：

python - <<'PY'
import torch

print("PyTorch:", torch.__version__)
print("CUDA available:", torch.cuda.is_available())
if torch.cuda.is_available():
    print("CUDA runtime:", torch.version.cuda)
    print("GPU:", torch.cuda.get_device_name(0))
    total = torch.cuda.get_device_properties(0).total_memory / 1024**3
    print(f"VRAM: {total:.2f} GiB")
    x = torch.randn(2048, 2048, device="cuda", dtype=torch.float16)
    y = x @ x
    torch.cuda.synchronize()
    print("FP16 CUDA matmul:", tuple(y.shape), "OK")
PY
验收含义 nvidia-smi 成功只证明 WSL 看到了 GPU。PyTorch 检查进一步证明当前 Python 环境、CUDA 运行时和实际张量计算可以协同工作。
