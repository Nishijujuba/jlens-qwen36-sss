Lesson 0002

沿代码追踪一次 J-lens 请求

本课把仓库拆成三条路径：读取模型内部状态、拟合 lens、修改模型内部状态。学习者只需先看数据如何流动，无需立即理解 Metal 内核或全部数学推导。

约 20 分钟 代码地图 读出与干预

一句话总领：浏览器把消息发给 FastAPI，模型逐层生成并捕获残差流，lens 把每层残差转换到最终层坐标系，服务器选出 top-k 词元并流式返回；干预会在指定层写入残差流，再让后续层继续计算。

1. 为什么先追踪请求

该仓库同时包含模型加载、自动微分、分析式 Jacobian、缓存解码、自定义 Metal 内核、后端接口和前端可视化。逐文件从头读到尾会快速丢失主线。

更有效的顺序是围绕一个问题追踪数据：

  1. 输入文本在哪里进入系统？
  2. 残差流在哪里产生和被捕获？
  3. Jacobian 矩阵在哪里应用？
  4. 词元分数在哪里生成？
  5. 干预在哪里写入？
阅读原则 第一遍只认清“输入、输出、形状和副作用”。第二遍再研究公式和性能优化。自定义内核属于第三遍内容。

2. 路径 A：读取中间层

A1浏览器发请求web/index.html
A2后端接收serve.py
A3逐层推理model.py
A4Lens 运输lens.py
A5选 top-kserve.py
A6网格呈现位置 × 层

A1–A2：浏览器进入 FastAPI

jlens_qwen/serve.py 是后端入口。启动时，它先确定 lens 文件，再加载模型和 lens。聊天界面使用 /api/chat_stream 接口，以服务器发送事件（SSE）持续返回新词元和每层读出。

SSE 可以理解为一条单向流水管：浏览器先发起一次请求，服务器随后分批推送事件。生成一个词元后即可更新界面，无需等待整段回答结束。

A3：模型逐层计算并捕获残差流

jlens_qwen/model.py 中的 StreamSession.extend() 接收新增词元 id。它完成以下工作：

  1. 把词元 id 转成嵌入向量。
  2. 依次执行所有模型层。
  3. 在指定层保存 hidden，形成 acts[layer]。
  4. 对最终状态做归一化和输出头计算，得到下一个词元 logits。
  5. 更新 KV cache 或 GDN 递归缓存，下一步仅计算新增词元。
hidden = text.embed_tokens(ids)
for layer_index, layer in enumerate(model.layers):
    hidden = layer(hidden, mask=mask, cache=cache)
    if layer_index in capture_layers:
        acts[layer_index] = hidden
final = text.norm(hidden)
logits = model.unembed(final[:, -1, :])

上面的代码是结构化简化。关键对象的形状为：

对象含义形状
hidden当前批次、当前词元位置的残差流[1, 新词元数, d_model]
acts[layer]某层执行后的残差流快照[1, 新词元数, d_model]
logits最后位置对整个词表的分数[vocab_size]

A4：把中间层运输到最终层坐标系

jlens_qwen/lens.py 中的 JacobianLens.transport() 执行核心矩阵乘法：

ĥℓ = Jℓ hℓ

代码采用行向量批量表示，因此实现写成 residual @ J.T。这与列向量公式 J @ h 表达同一线性变换。

J = lens.jacobian_mx(layer)       # [D, D]
transported = residual @ J.T      # [..., D]
logits = model.unembed(model.final_norm(transported))
常见误区：矩阵顺序 数学公式常把向量写成列向量；深度学习代码经常把特征放在最后一维并使用行向量批处理。因此公式里的 J @ h 在代码中会表现为 h @ J.T。

A5–A6：从完整词表压缩成网格

每个层、每个位置都可能产生约 25 万个词元分数。全部传给浏览器会造成巨大数据量。serve.py 使用分块 top-k 算法，只保留最高的少量词元 id 和分数，再通过 SSE 发给前端。

前端把结果放进二维网格：

  • 纵轴：序列位置，即每个输入或生成词元。
  • 横轴：模型层。
  • 单元格：该位置、该层的 top-1 J-lens 词元。
  • 详情面板：top-10、分数和干预入口。

3. 路径 B：拟合 Jacobian lens

读取路径需要已有的 J_ℓ。这些矩阵来自 fit_analytic.py。

B1准备提示词覆盖多种文本上下文
B2捕获各层激活保存线性化位置
B3算局部 JacobianMℓ = ∂hℓ+1/∂hℓ
B4链式相乘连接到最终层
B5跨提示词平均得到通用近似
B6保存 NPZ服务器后续加载

从靠近输出的层向前递推：

Jℓ-1 = Jℓ Mℓ

Mℓ 描述第 ℓ 层输入轻微变化时，该层输出怎样变化；Jℓ 描述该层输出怎样影响最终层。两者相乘，把影响继续向前连接。

类比：多段汇率 已知“美元到欧元”的局部兑换比例，又知道“欧元到日元”的局部兑换比例，两段相乘可估算“美元到日元”的局部比例。链式法则承担同样的连接作用。

跨提示词求平均会降低单个上下文的偶然性，同时会抹平上下文特有结构。20 个提示词适合演示；更多提示词通常带来更稳定的 lens，也增加拟合成本。

4. 路径 C：写入残差流

读出回答“当前状态沿哪些词元方向得分高”。干预回答“修改该方向后，后续计算是否按预测变化”。主要代码位于 interventions.py 和 model.py。

C1界面创建规格模式、层、位置、词元、强度
C2构造概念方向vt = JℓTWU[t]
C3编译层编辑按层和位置组织
C4执行层后写入修改 hidden
C5下游继续计算缓存也接收修改后状态
C6A/B 对比基线与干预结果

概念方向从哪里来

vt = JℓT WU[t]

W_U[t] 是词元 t 在最终输出空间中的方向。乘上 J_ℓ.T 后，它被拉回到第 ℓ 层的残差空间。沿 vt 增加残差，通常会提高该词元的 J-lens 读出分数。

界面操作内部含义直觉
Replace交换源方向和目标方向的坐标把“法国”分量换成等强度的“中国”分量
Addh ← h + αv_t增加目标方向
Removeh ← h − αv_t削弱目标方向
Erase投影掉一组方向张成的子空间移除这些方向能够解释的分量

修改发生在什么位置

StreamSession.extend() 在某层完成计算后，先应用该层编辑，再保存激活并交给下游层。这样，界面看到的是修改后的单元格，后续层与缓存也接收到修改后的状态。

hidden = layer(hidden, ...)
hidden = apply_edits(hidden, edits_for_this_layer, position)
acts[layer_index] = hidden
# 下一层继续读取 hidden

6. 十分钟代码定位练习

  1. 在 serve.py 中找到启动加载函数，并确认默认模型 id。
  2. 在 model.py 中找到 StreamSession.extend()，标出嵌入、层循环、激活捕获和 logits 四行。
  3. 在 lens.py 中找到 transport()，写出输入和输出形状。
  4. 在 interventions.py 中找到 steer() 与 patch_swap()，分别用一句自然语言解释。
  5. 在 fit_analytic.py 中找到 J_current = J_current @ M_l，说明它对应哪条链式法则公式。
